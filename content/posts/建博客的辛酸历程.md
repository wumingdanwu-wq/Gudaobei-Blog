# 从零搭建个人博客的辛酸历程

今天，我终于拥有了属于自己的一个小角落：

**zidane.us.ci**

一个看起来很普通的网址，但是对于我来说，它背后藏着一段不太普通的折腾经历。

---

## 为什么突然想建一个博客？

其实这个想法已经存在很久了。

过去几年，我一直喜欢折腾各种数字项目：

- VPS服务器
- 网络环境
- Linux系统
- AI工具
- GitHub项目
- 各种效率工具

但是有一个问题：

**折腾完以后，东西散落得到处都是。**

今天研究一个工具，写一点笔记；

明天搭一个服务器，记录一点配置；

后天又发现一个AI玩法，收藏几个链接。

结果几年下来，最大的成果可能不是学会了多少东西，而是：

> 我收藏了一大堆东西，但是找不到它们在哪里。

所以，我决定建立一个属于自己的数字空间。

---

## 第一次遇见 Hugo

选择博客系统的时候，我也纠结过。

一开始觉得：

“是不是直接做一个网页就好了？”

后来发现，如果每次写文章都改网页，那估计还没开始写文章，我已经先被代码劝退了。

于是遇到了 Hugo。

它的理念很简单：

写 Markdown。

然后自动生成网站。

听起来非常美好。

当然，实际开始以后……

事情并没有这么简单。

---

## 第一关：Hugo 安装和主题折腾

刚开始的时候，我以为：

“安装一下，换个主题，不就完成了吗？”

事实证明：

程序员的“不就”三个字，通常代表后面还有很多坑。

主题、配置文件、目录结构，一个个看过去。

尤其是：

```text
hugo.toml
content
layouts
themes
```

这些文件夹第一次看到的时候，感觉像进入了一个陌生城市。

每条路都认识几个字，但是组合起来完全不知道往哪里走。

---

## 第二关：Markdown格式事故现场

Markdown看起来很简单：

三个横杠：

```
---
```

下面写标题、日期、标签。

但是就是这么几个字符，也能制造各种问题。

有时候：

- 多一个空格
- 少一个缩进
- 文件格式不对

网站马上告诉你：

“不行，重新来。”

那一刻感觉：

自己不是在写博客。

而是在和一个非常严格的机器人老师考试。

---

## 第三关：GitHub自动部署

以前上传网站，我理解的是：

打开网页。

点击上传。

等待完成。

但是 Hugo + GitHub 的方式完全不同：

```
修改文章
 ↓
git add
 ↓
git commit
 ↓
git push
 ↓
GitHub自动生成网站
```

第一次看到这些命令：

说实话，有一点懵。

感觉自己突然从普通用户变成了一个“半吊子程序员”。

---

## 最大的挑战：GitHub Actions

本以为：

“上传代码，网站应该就好了。”

结果第一次运行：

红色失败。

第二次：

还是红色。

第三次：

继续红色。

各种错误：

- Hugo构建失败
- YAML格式错误
- GitHub Pages没有开启
- 部署权限问题

看着 GitHub Actions 页面上的红叉：

真的有一种感觉：

> 我只是想写个博客，为什么感觉像在参加服务器工程师考试？

---

## 最后的成果

经过不断修改：

终于看到：

绿色的：

```
deploy ✅
```

那一刻还是挺开心的。

因为这不仅仅是一个网站上线。

它代表：

我终于建立了一个自己的数字空间。

这里以后会记录：

- 技术学习
- AI探索
- 网络折腾
- 工具收藏
- 生活思考

也许多年以后回来看看，会发现：

今天这个简单的博客，就是未来很多项目的起点。

---

## 写在最后

建博客最大的收获，并不是拥有一个网站。

而是在这个过程中：

重新认识了工具。

认识了代码。

也认识了自己。

折腾还会继续。

欢迎来到：

**古道北的数字空间。**
