## 第二关：为什么新人进群，机器人却高冷不说话？

我兴致勃勃地写了 `ChatMemberHandler` 来监听新成员进群。

满怀期待地拉人进群测试。

结果：

群里安安静静，机器人一句话也没说。

检查代码，没有报错。

检查网络，完全正常。

折腾了一圈才发现，原来掉进了两个新手最容易踩的坑：

1. **权限问题**：在 Telegram 里，机器人必须被设为“群组管理员”，服务器才会把成员变动的消息发给它。

2. **默认屏蔽问题**：启动轮询时如果只写 `app.run_polling()`，Telegram 默认不会推送群成员变动事件。

必须改成下面这样，显式开启全部事件监听：

Python

```
app.run_polling(allowed_updates=Update.ALL_TYPES)
```

改完代码，加上管理员权限，再次测试：

群里终于弹出了那句期待已久的：

> 👋 欢迎加入古道北技术交流群！

那一刻，比写出一百行代码还有成就感。

## 第三关：从“纯文本回复”进化到“全能助手”

解决了入群欢迎，我又开始停不下来了。

之前的 `/status` 指令，返回的只是我自己写死的一句“✅ 在线”。

这显然不够真实。

于是我对机器人做了一次全面升级：

- **加入底部交互按钮（Inline Keyboard）**：不用再手动敲命令，点击消息下方的按钮就能一键跳转到博客、景观设计网站和频道。

- **自动注册左下角菜单**：启动时自动把所有指令写入聊天框左下角菜单。

- **真正的实时网站测速**：用 `httpx` 实时请求我的博客和项目网站，直接计算出响应延迟（毫秒）。

- **关键词自动接话**：在群里只要聊到“博客”、“景观”、“频道”，机器人就会自动递上链接卡片。

## 终极折腾：Hugo 博客与 Telegram 频道全自动同步

最让我满意的功能，是打通博客和频道的任督二脉。

以前写完文章的流程是：

写文章 ➔ 上传 GitHub ➔ 等待部署 ➔ 手动复制链接去群里和频道发通知。

现在，我给机器人加上了 **RSS 自动监测功能**。

因为 Hugo 每次生成网站时，都会自动更新 `index.xml`。

现在的自动化流程变成了这样：

Plaintext

```
本地写好 Markdown 文章
 ↓
git push 推送到 GitHub
 ↓
GitHub Actions 自动构建部署 ✅
 ↓
古道北助手检测到 index.xml 更新
 ↓
自动排版并推送到「古道北技术动态」频道
 ↓
自动转发并置顶到技术交流群
```

整个过程完全不需要人工干预。
