这次折腾的起点很朴素：

> “让 Ubuntu 虚拟机也能用上代理。”

结果一路敲了一大堆命令，做完之后我自己都不知道刚才干了些什么。

于是有了这篇——不是教程，只是一份**真实的折腾记录**，顺便把这一路到底做了什么理清楚。

## 一、最重要的一点，居然不是 V2rayA

整个过程下来，我最大的体会是：

> **先让 Ubuntu 自己能够正常联网，再在 Ubuntu 里面解决代理问题。**

虚拟机连网都不通，后面装得再漂亮的 V2rayA 也只是一堆摆设。

所以这次我没有让 Ubuntu 去“蹭” Windows 宿主机的代理，而是给虚拟机配了一套**自己的独立网络**。配好之后，Ubuntu 拿到了属于自己的局域网地址，V2rayA 也能监听到类似这样的地址：

```text
127.0.0.1:2017
192.168.0.104:2017
```

- `127.0.0.1`：Ubuntu 自己（“本机”）
- `192.168.0.104`：这台虚拟机在局域网里的地址

思路就是：**把代理环境尽量关在 Ubuntu 自己家里**，不去麻烦宿主机。

## 二、第一个坑：时间不对，HTTPS 全崩

刚开始，虚拟机的网络和时间同步并不太正常。

结果是什么呢？访问 HTTPS 网站时各种证书报错，`certificate verify failed` 之类的字样扑面而来。我第一反应当然是“代理坏了”“网站挂了”——

然而罪魁祸首是：**系统时间不对**。

教训：遇到 SSL / HTTPS / 证书相关的报错，先敲一句 `date` 看看时间，别急着怀疑人生。看起来很简单，排查的时候却最容易被忽略。

## 三、V2rayA 的“零件清单”

装的时候我才发现，这件事不是“装一个软件”，而是要凑齐几样东西：

| 零件                    | 干什么的                     |
| ----------------------- | ---------------------------- |
| V2rayA                  | 管理界面 / 配置管理          |
| V2Ray Core              | 真正处理代理连接的“干活的”   |
| geoip.dat / geosite.dat | 网络地址与域名分类的数据文件 |

最容易搞混的是：**V2rayA 并不是 V2Ray Core**。前者像“控制台”，后者才是“发动机”。所以光有 V2rayA 不行，还得给它配一个 Core。

另外，Linux 下载下来的程序默认**不一定有执行权限**，要先 `chmod +x` 一下，否则它就只是一个安静躺在 Downloads 里的文件。

## 四、启动命令：整件事里最关键的一行

```bash
~/Downloads/v2raya_linux_x64_2.5.10 --v2ray-bin ~/Downloads/v2raya_core_linux_x64_2.5.10
```

拆开看其实很好懂：

- 前半截是 V2rayA 本体；
- `--v2ray-bin` 是在告诉它：“Core 在哪”；
- 后半截就是 Core 的路径。

整句翻译成人话：**启动 V2rayA，并且告诉它用这个 Core。**

## 五、第二个坑：网页能关，终端不能关

启动成功后，浏览器打开 `http://127.0.0.1:2017` 就能进入 V2rayA 的管理页面。

这里的 `127.0.0.1` 不是什么神秘的外部网站，意思就是“**我自己**”——Ubuntu 本机的 2017 端口。

但是！**那个运行着 V2rayA 的终端窗口，才是 V2rayA 本人。** 网页只是它开的一扇窗：

- 网页关了 → 没事，再开就是了；
- 终端关了 → V2rayA 当场下班。

所以整个测试阶段，我都是老老实实让终端开在那儿，当一个“不能碰的窗口”。

## 六、节点、代理组、代理模式

进入管理页面、创建好管理员账号之后：

1. **导入节点**：把自己的订阅或节点配置导进去；
2. **建代理组**：别看到节点多就一股脑儿全用，把它们放进一个代理组，以后切换不用重新配置整套代理；
3. **选模式**：我最后用的是 **大陆白名单模式**。

代理组里可以用自动选择、URL 测试、故障切换这些方式，当然想手动指定某个节点也完全可以。

大陆白名单模式的效果很符合我的需求：

```text
国内网站  → 正常直连
需要代理  → 走代理节点
```

而不是让所有流量不分青红皂白都绕一圈。实测之后，Google、YouTube 都能正常访问。

## 七、这次真正的收获：把“代理”拆成六层

以前我对代理的理解是：

```text
打开代理软件 → 选节点 → 能上网
```

现在知道，里面其实有这么多层：

```text
Ubuntu 22.04
     │
     ▼
独立网络
     │
     ▼
  V2rayA
     │
     ▼
V2Ray Core
     │
     ▼
   节点池
     │
     ▼
   代理组
     │
     ▼
  代理规则
   ↙     ↘
国内直连   需要代理 → 节点
```

拆开之后最大的好处是：以后出问题，可以**一层一层往上排查**，而不是只会感叹一句——

> “代理怎么又不能用了？”
